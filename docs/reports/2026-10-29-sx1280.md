# SX1280 / Ebyte E28 backend and 2.4 GHz-only operation (simulation)

Date: 2026-10-29. No hardware involved; numbers from `sim/loopback`,
`common/tests/test_airsched` and `sim/m1_link.py` on the simulated ether.

## What the SX1280 can do for this link

| | LR2021 | SX1280 |
|---|---|---|
| Bands | 868 MHz + 2.4 GHz | 2.4 GHz only |
| FLRC bit rates | 2600 ... 260 kbit/s | 1300, 1040, 650, 520, 325, 260 kbit/s |
| FLRC coding rates | 1/2, 3/4, 2/3, 1 | 1/2, 3/4, 1 |
| Max FLRC payload | 255 B | **127 B** (datasheet rev 3.2, payload length 6..127) |
| Chip output | -19..+12 dBm (2.4 GHz) | -18..+13 dBm |
| Link modes it can run | all four | **hq1300 only** |

So an SX1280 system is a 2.4 GHz-only system with HQ 1.3 Mbit/s (720p30).
LR (868 MHz) and HQ 2.6 Mbit/s (720p60) need the LR2021.

Sources: SX1280 datasheet rev 3.2 (FLRC packet parameters); RadioLib 7.8.1
`SX128x` driver (`setBitRate`, `setCodingRate`, `checkOutputPower`).

## Capacity: 127-byte packets

Same scheduler model as before (`common/airtime.h`, still unmeasured
constants), hq1300, CR 3/4, two beacons per hop, RS 8/12:

| Chip | Packet | Packets/hop | Shard bits | Video capacity |
|---|---|---|---|---|
| LR2021 | 247 B | 4 | 752 kbit/s | 501 kbit/s |
| SX1280 | 127 B | 7 | 644 kbit/s | **429 kbit/s** (-14 %) |

The 12-byte header and the per-packet preamble, sync, CRC and gap weigh
twice as much in 127-byte packets. The CLAUDE.md CBR target for HQ 1.3M is
~850 kbit/s, so the gap to the target (already open for the LR2021) is
larger with the SX1280.

## M2 picture recovery, hq1300, one receiver, 20 % random loss

`loopback --mode hq1300 --chip lr2021|sx1280 --seconds 6 --rx loss=0.2,seed=S`,
640x360 clip, encoder CBR at 85 % of capacity:

| Chip | Seed | Complete frames | Worst bad stretch | Gate |
|---|---|---|---|---|
| LR2021 | 1 | 81.1 % | 0.43 s | PASS |
| LR2021 | 2 | 77.8 % | 0.93 s | PASS |
| LR2021 | 3 | 86.1 % | 0.93 s | PASS |
| LR2021 | 4 | 83.3 % | 1.33 s | FAIL |
| SX1280 | 1 | 72.2 % | 1.03 s | FAIL |
| SX1280 | 2 | 73.9 % | 0.60 s | PASS |
| SX1280 | 3 | 77.2 % | 0.90 s | PASS |
| SX1280 | 4 | 81.7 % | 0.90 s | PASS |

HQ 1.3M with a single receiver at 20 % loss is marginal on both chips; the
SX1280 is in the same range, with a few % fewer complete frames because a
frame is split into more, smaller blocks (3 slices instead of 2).

## M1 on the simulated ether

`sim/radio_sim.c` now emulates the chip from the radio conf: it refuses
settings the chip cannot do, applies its packet limit on TX and RX, and a
receiver only hears packets with the same bit rate and coding rate.

Simulator fix found on the way: the simulated radio timestamped a packet
when the receiving process read it, not when it was sent. A VRX descheduled
on a loaded PC then computed a late hop start from a beacon, retuned late on
every following hop and missed the next beacons too (the error only heals
through a beacon), so `m1_link_lr520` failed its PER check in 4 of 12 runs
on the previous commit (measured loss 26-52 % for 20 % configured). Packets
now carry their TX start time (all processes share CLOCK_MONOTONIC, as the
kernel IRQ timestamp does on hardware), and a receiver hears a packet only
if it was listening on that channel when the packet started: 0 of 12
failures, and 3 x 15/15 with all tests run in parallel, gcc and clang.

| Test | Setup | First lock (5 runs x 2 VRXs) | Air overruns / run |
|---|---|---|---|
| `m1_link_lr520` | LR2021, lr520, 20 % loss | 35 - 173 ms | 1 - 4 |
| `m1_link_hq2600` | LR2021, hq2600, 10 % loss | 38 - 356 ms | 3 - 8 |
| `m1_link_e28` | E28 air + 2 E28 VRXs, `mode=auto` (= hq1300 only), 10 % loss | 12 - 374 ms | 7 - 15 |
| `m1_scan_2g4` | LR2021 air on hq1300, LR2021 VRXs `band=2400 mode=auto` (scan hq2600, hq1300), 10 % loss | 849 - 1232 ms | 3 - 9 |

The scan always loses one 810 ms park period on hq2600 first, so a VRX
restricted to 2.4 GHz with both HQ rates allowed locks in up to ~1.6 s worst
case (810 ms + 790 ms). Fix the mode (`mode=hq1300`) to get under 1 s.

The E28 air logs more overruns (7 packets per hop, so more chances to be
late) on this PC without `--rt`; to be measured on the RV1103.

## To verify on hardware (docs/m0-bench.md, section 8)

- E28 TXEN/RXEN levels per mode, and that RX -> TX never has both high.
- Continuous RX keeps receiving after each RX_DONE (the backend reads the
  buffer directly instead of RadioLib's `readData()`, which goes to standby).
- PA gain (preset: 25 dB, from the ExpressLRS "DIY 2400 E28" target: SX1280
  -15..-1 dBm = 10..250 mW) and LNA gain (preset: 12 dB, RSSI correction).
- FLRC airtime and retune time on the SX1280.
- Whether LR2021 and SX1280 FLRC interoperate on air (same sync word, CRC
  length, header). RadioLib's SX128x `setCRC()` shares its length encoding
  with GFSK; the datasheet's FLRC CRC-length table should be checked against
  an LR2021 receiver before mixing chips in one link.
